# Neovim のアイコンプラグイン比較

調査日: 2026-11-07

対象は **mini.icons** と **nvim-web-devicons**。ほかの候補は、ファイルアイコン・補完アイコン・アイコン検索という用途の違いも含めて比較する。

## 選び方

| 優先すること | 候補 | 理由 |
| --- | --- | --- |
| テーマになじむ配色、ファイルと LSP の統一 | mini.icons | 共通の色グループと、ファイル・ディレクトリ・LSP の API がある |
| 既存の devicons 設定・連携を活用 | nvim-web-devicons | devicons API を使う設定をそのまま利用でき、アイコンごとの色も指定しやすい |
| Nerd Font を使えない環境 | mini.icons | `style = 'ascii'` で文字表示に切り替えられる |
| 補完候補だけ VS Code 風にしたい | lspkind.nvim | 補完の種類に対応するアイコンと整形機能がある |
| 設定に使う記号を探したい | nerdy.nvim / icon-picker.nvim | アイコンを検索して挿入・コピーできる |
| Vim と旧来の Vim プラグインを共用 | vim-devicons | NERDTree、vim-airline などとの連携がある |

今回の dotfiles ではすでに両方が使われている。**現状のカスタム設定を生かすなら nvim-web-devicons、表示をまとめるなら mini.icons を軸に検討**するのがよさそう。これは後述のローカル設定を踏まえた判断。

## mini.icons と nvim-web-devicons

両方とも、ほかのプラグインへアイコン文字や色情報を渡すライブラリ。インストールしただけですべての UI が切り替わるわけではなく、表示側の対応・設定が必要。

| 比較項目 | [mini.icons](https://github.com/nvim-mini/mini.icons) | [nvim-web-devicons](https://github.com/nvim-tree/nvim-web-devicons) |
| --- | --- | --- |
| 配布 | mini.nvim の一部。単体でも導入可能 | 単独の Lua プラグイン |
| 見た目の傾向 | Material Design 系の `nf-md-*` を優先 | Devicons 系の `nf-dev-*` を中心に採用 |
| 色 | 9 種類の共通ハイライト。テーマに合わせてまとめて調整しやすい | 個別のハイライトと色。ライト／ダークのバリアントにも対応 |
| ファイルの判定 | 明示的な対応表に加え、Neovim の filetype 判定へフォールバック | ファイル名・拡張子の対応表が基本。filetype 用 API もある |
| 主な対象 | ファイル、拡張子、filetype、ディレクトリ、OS、LSP kind | ファイル、拡張子、filetype、OS、デスクトップ環境、ウィンドウマネージャー |
| 未知の対象 | カテゴリーごとの既定アイコンを返す | `default = true` で既定アイコンを返す。設定によっては `nil` |
| Nerd Font なし | ASCII スタイルあり | 同等の組み込みスタイル切り替えはない |
| カスタム設定 | `file` / `extension` / `filetype` などに `glyph` と `hl` を指定 | `override_by_filename` / `override_by_extension` などに `icon` と `color` を指定 |
| 既存 devicons API との連携 | `mock_nvim_web_devicons()` で取得 API を代替可能 | 本来の実装をそのまま利用 |

性能は一律に優劣を付けにくい。mini.icons は取得結果をキャッシュするが、初回に `vim.filetype.match()` へ進む場合には追加コストがある。ここでは速度のベンチマークは実施していない。

出典: [mini.icons 公式ヘルプの比較・API 説明](https://github.com/nvim-mini/mini.icons/blob/main/doc/mini-icons.txt)、[nvim-web-devicons の設定・API 説明](https://github.com/nvim-tree/nvim-web-devicons#usage)。

## 実際のアイコンを並べる

以下は、この環境にインストール済みの両プラグインを **ユーザーの上書き設定なし**で読み込み、API から取得した結果。最新版全体の比較ではなく、手元のバージョンでのサンプル。

mini.icons は `get('file', name)`、nvim-web-devicons は `strict = true` と `default = true` を指定した `get_icon()` を使用した。

| `init.lua` |  |  |
| `main.rs` | 󱘗 |  |
| `main.py` | 󰌠 |  |
| `index.ts` | 󰛦 |  |
| `index.tsx` |  |  |
| `README.md` |  | 󰂺 |
| `config.toml` |  |  |
| `config.yaml` |  |  |

`init.lua` はファイル名固有の結果なので、すべての `.lua` ファイルが同じ表示になるとは限らない。`main.mbt` は両方ともこの条件では既定アイコンだったが、現在の dotfiles の devicons 設定では `󱩡` に上書きされる。

Markdown の表ではプラグインのハイライト色は再現されない。また、閲覧側のフォントにグリフがないと四角などになる。形・幅・色の最終判断は、普段の端末と Neovim で行う。

### Neovim 内で確認する

nvim-web-devicons は、プラグインを読み込んだ後に次を実行するとアイコンと色を一覧表示できる。

```vim
:NvimWebDeviconsHiTest
```

mini.icons は、例えば次でアイコンとハイライトグループを取得できる。

```vim
:lua print(require('mini.icons').get('file', 'main.rs'))
:lua print(require('mini.icons').get('directory', '.github'))
:lua print(require('mini.icons').get('lsp', 'Function'))
```

グリフ表示の目安は mini.icons が Nerd Fonts 3.0 以降、調査時の nvim-web-devicons が 3.3 以降。出典: [mini.icons のフォント要件](https://github.com/nvim-mini/mini.icons/blob/main/doc/mini-icons.txt)、[nvim-web-devicons の要件](https://github.com/nvim-tree/nvim-web-devicons#requirements)。

## ほかの候補

| プラグイン | 用途・特徴 | mini.icons / web-devicons との関係 |
| --- | --- | --- |
| [lspkind.nvim](https://github.com/onsails/lspkind.nvim) | 補完候補の Function・Class などにアイコンを付ける。Nerd Fonts と Codicons のプリセット、nvim-cmp 用の整形関数がある | 補完部分の候補。ファイルアイコン全体の置き換え用途とは異なる |
| [vim-devicons](https://github.com/ryanoasis/vim-devicons) | Vimscript ベース。NERDTree、vim-airline、CtrlP などにファイルアイコンを追加 | Vim 側の連携が必要なら候補。Lua の devicons API をそのまま代替するものではない |
| [nerdy.nvim](https://github.com/2KAbhishek/nerdy.nvim) | Nerd Font のグリフを検索・挿入。`:Nerdy` で一覧。名前指定の取得 API もある | カスタムアイコン選びの補助。ファイル名からの自動判定を置き換える用途ではない |
| [icon-picker.nvim](https://github.com/ziontee113/icon-picker.nvim) | Nerd Font、絵文字、記号などを選択・挿入・ヤンク | 設定や文章へ記号を入力する補助 |

各行のリンクは公式リポジトリ。ファイルアイコンの供給元を比較するなら、まず mini.icons と nvim-web-devicons の 2 つを比べればよい。

## この dotfiles での使われ方

設定ファイルを静的に確認した結果。実際の表示はロード順や有効化状態にも依存する。

| 設定 | 確認できた利用方法 |
| --- | --- |
| [oil-nvim.lua](../config/nvim/lua/plugins/oil-nvim.lua) | mini.icons を依存として指定し、`opts = {}` でセットアップ |
| [blink-cmp.lua](../config/nvim/lua/plugins/blink-cmp.lua) | mini.icons の `lsp` カテゴリーから補完アイコンと色を取得 |
| [lualine.lua](../config/nvim/lua/plugins/lualine.lua) | nvim-web-devicons の依存指定と `get_icon_by_filetype()` の直接呼び出し |
| [neo-tree.lua](../config/nvim/lua/plugins/neo-tree.lua)、[bufferline.lua](../config/nvim/lua/plugins/bufferline.lua) | nvim-web-devicons の依存指定 |
| [nvim-web-devicons.lua](../config/nvim/lua/plugins/nvim-web-devicons.lua) | `toml`・`elv`・`tl`・`nrs`・`mbt` のアイコンと色を上書き |

両方を導入しても、上書き設定が自動で共有されるわけではない。今の構成では、同じファイルでも表示するプラグインによってアイコンや色が異なる可能性がある。

### mini.icons にまとめる場合

1. 上記 5 拡張子のカスタム設定を mini.icons に移す。
2. 表示側のプラグインが mini.icons に直接対応しているか確認する。
3. devicons API のみを使う箇所には、必要に応じて互換機能を設定する。
4. Oil、Neo-tree、lualine、bufferline、補完で実際の表示を確認する。

mini.icons 側の設定例（設定ファイルへの適用はしていない）:

```lua
require('mini.icons').setup({
  extension = {
    mbt = { glyph = '󱩡', hl = 'MiniIconsPurple' },
    elv = { glyph = '󰘧', hl = 'MiniIconsGreen' },
  },
})

-- devicons の取得 API を使うプラグインより前に実行する
require('mini.icons').mock_nvim_web_devicons()
```

互換機能は完全に同一の動作を保証するものではない。例えば `set_icon()` などの変更 API は空実装で、元の devicons の上書き設定を引き継ぐ仕組みもない。独自色を厳密に残すなら mini.icons 側でも専用ハイライトを定義する。出典: [互換機能の実装](https://github.com/nvim-mini/mini.icons/blob/main/lua/mini/icons.lua)。

今の用途なら、まず上の表で形を比較し、次に「mini.icons の共通配色」と「devicons の個別配色」のどちらが好みかを Neovim 内で確認するのが選びやすい。
